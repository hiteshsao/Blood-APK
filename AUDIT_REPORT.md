# LifeDrop System Audit Report

**Audit Date**: October 21, 2026  
**Auditor**: Senior Software Auditor (Backend, Mobile, Security, QA)  
**Target Git Branch**: `audit/2026-10-21`  
**Scope**: End-to-end verification of `lifedrop/backend` (Spring Boot 3.2.5), `lifedrop/web` (React 18 + Vite), and `lifedrop/mobile` (Expo SDK 57 / React Native) across build prompts 3 through 17.

---

## Executive Summary

### What Works (VERIFIED)
- **Role-Based Authentication & Security**: Complete stateless JWT authentication with BCrypt hashing, strict role differentiation (DONOR vs RECIPIENT), and validated registration rules (donor blood group, age 18–65, 10-digit mobile, 8-character password). Security filter chains protect `/api/donor/**` and `/api/recipient/**` with clean JSON 401/403 handlers.
- **Clinical Matching & Haversine Distance**: Clinical immunohematology compatibility for all 8 blood groups is strictly applied via `BloodCompatibility`. Native Haversine SQL queries and `DistanceCalculator` calculate distances accurately.
- **Core Request Lifecycle**: Full request-response cycle from creation (10 km NORMAL, 25 km URGENT), individual `RequestResponse` allocation, transactional first-accept-wins (HTTP 409 conflict detection), through request completion (which stamps donor's `lastDonatedDate` to today). Automatic background `@Scheduled` job expires pending requests older than 24 hours every 15 minutes.
- **Emergency SOS Broadcast**: End-to-end emergency alert system (`POST /api/recipient/sos`) broadcasting within 25 km, auto-escalating to 50 km if zero donors are found, enforcing a 1-active-SOS cap and 6-hour expiry window. Both web modal and mobile animated radar screen with direct emergency calling buttons (`112` and `108`) work seamlessly.
- **Notifications**: Resilient notification architecture where every event creates an in-app database notification and attempts Expo push notification without ever failing the primary transaction if network or push token issues occur.
- **Donor Gap & Location Throttling**: Strict 90-day recovery rule enforced upon availability toggle. Mobile donor location syncing is strictly throttled to at most once every 30 minutes.
- **Account Anonymization**: Permanent PII scrubbing and account deactivation via `DELETE /api/users/me`.

### What is Missing or Broken
1. **Safety Reporting in Mobile (MISSING)**: `POST /api/requests/{id}/report` is fully implemented in Backend and Web, but completely absent from the Mobile app. Donors and recipients on mobile cannot report suspicious requests.
2. **Dev Seed Data Geographic Inconsistency (PARTIAL / DISCREPANCY)**: The specification required 12 donors in Bhopal, but `DevDataLoader.java` seeds donors in Indore (~190 km away). When users test in Bhopal (the default fallback in `RegisterScreen.js`), zero seed donors match within the 10/25 km search radius.
3. **Web Donor Dashboard Skips Details Endpoint (PARTIAL)**: `DonorDashboard.jsx` relies entirely on local list state instead of invoking `GET /api/donor/requests/{id}`.
4. **Missing Backend Stats Endpoint (BROKEN LINK)**: Web's `StatsStrip.jsx` queries `GET /api/stats`, which does not exist on Backend (returns 404 in console; defaults to 0).
5. **Hard-Coded Mock Requests in Web Guest Mode (DATA SMELL)**: `BloodRequests.jsx` hard-codes 3 fake dummy requests when viewed without authentication.
6. **Development Test Endpoints Exposed in Production**: `GET /api/donor/test` and `GET /api/recipient/test` are present in controllers without `@Profile("dev")` gating.

   - *Detail*: `POST /api/requests/{id}/report` is fully operational in Backend and Web, but Mobile lacks `reportRequest` in `requestApi.js` and has no Report button in `RequestDetailScreen.js` or `RequestStatusScreen.js`. Mobile users have no way to flag abusive or fraudulent requests.

   - *Status*: Partial / Data Discrepancy.
   - *Detail*: Prompt 8 explicitly specifies `dev-profile seed (12 Bhopal donors + 2 recipients)`. `DevDataLoader.java` seeds donors in Indore (~190 km away). When Mobile defaults to Bhopal GPS (e.g. `RegisterScreen.js:45`), zero donors are matched within 10 km or 25 km.

   - *Detail*: `StatsStrip.jsx:17` invokes `apiClient.get('/api/stats')` to display real-time donor and request counts. Because no controller provides this endpoint, the request fails with a 404 error and displays zeroes.

   - *Detail*: Mobile's `SosStatusScreen.js:98-100` polls every 10 seconds to update donor acceptance in real time. Web's `SosModal.jsx` and `EmergencySos.jsx` do not poll periodically and require manual page refresh or action clicks.
